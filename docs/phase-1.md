# Phase 1 — Customer, Account and Ledger Foundation

## Scope delivered

- Create and retrieve customers. Email is trimmed and normalized to lowercase; database uniqueness remains the final concurrency-safe guard.
- Create and retrieve customer accounts. Account numbers are generated by the server; the caller cannot choose an owner or opening balance.
- Retrieve account balance. New accounts start at exactly zero and are ACTIVE only when created for an ACTIVE customer.
- Introduce stable API error responses for validation, missing resources and uniqueness conflicts.
- Add a pure ledger journal validator requiring at least two positive entries, one currency per journal, and total debits equal total credits.

## API

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/v1/customers` | Create customer |
| GET | `/api/v1/customers/{customerId}` | Retrieve customer |
| POST | `/api/v1/accounts` | Open account for an existing customer |
| GET | `/api/v1/accounts/{accountId}` | Retrieve account |
| GET | `/api/v1/accounts/{accountId}/balance` | Retrieve current balance projection |

### Create customer

```json
{ "firstName": "Alex", "lastName": "Tan", "email": "alex.tan@example.test", "phoneNumber": "+60123456789" }
```

### Create account

```json
{ "customerId": "<customer UUID>", "accountType": "SAVINGS", "currency": "MYR" }
```

The response includes a generated 16-digit account number, account UUID, status and zero balance.

## Design notes

- This is an educational simulation, not a real bank. No identity verification, regulated onboarding, deposits or real money movement are implemented.
- The account balance is a projection, not an independently editable field. Phase 2 will update it only in the same database transaction as the corresponding ledger posting.
- `@Version` is present on the account projection for optimistic concurrency detection. Phase 2 will define and test the authoritative locking strategy for transfers.
- The journal validator is a domain guard only. Phase 2 implements persisted journal posting and balance updates atomically.
- Email uniqueness is enforced by PostgreSQL, not only by a pre-check.
